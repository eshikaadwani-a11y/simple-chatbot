# Resume Guidance for Engineers

## Structure
One page for students/early career. Sections: contact, education, experience,
projects, skills. Lead with the strongest content for the target role. Use a clean,
ATS-friendly layout — no tables, columns, or images that parsers choke on.

## Bullet points that land
Use the formula: action verb + what you did + impact (quantified) + how/tech. Lead
with strong verbs (built, designed, optimized, automated). Quantify everything:
"cut p95 latency 40%", "served 10k requests/day". Avoid responsibilities-only
phrasing; show outcomes.

## ATS optimization
Applicant Tracking Systems parse text and match keywords from the job description.
Mirror the role's key skills (languages, frameworks, concepts) where you genuinely
have them. Use standard section headers, a parseable font, and submit a PDF unless
told otherwise. Don't keyword-stuff.

## Projects section
For each project: a one-line description, the problem solved, the tech stack, and a
link (GitHub/live demo). A deployed project with a demo link and a clear README
beats five unfinished repos. Highlight scope, ownership, and measurable results.

## Common mistakes
Typos, walls of text, vague bullets, listing every technology shallowly, missing
links, and no quantified impact. Tailor the resume per role rather than sending one
generic version.
