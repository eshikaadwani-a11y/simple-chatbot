# Technical Interview Preparation

## Coding interview structure
A typical 45-minute coding interview: 5 min intro, 30 min problem solving, 10 min
questions. Use the UMPIRE / clarify-plan-code-test flow: Understand the problem,
ask about input size and edge cases, propose an approach with complexity, code it
cleanly, then test with examples and edge cases. Think out loud — communication is
scored as much as correctness.

## Behavioral interviews (STAR)
Answer behavioral questions with STAR: Situation, Task, Action, Result. Quantify
results. Prepare 6–8 stories covering conflict, failure, leadership, ambiguity, and
impact; reuse and reshape them per question. "Tell me about yourself" should be a
90-second narrative: present → past → why this role.

## System design basics
For design rounds: clarify requirements (functional and non-functional), estimate
scale (QPS, storage), define the API, sketch the high-level architecture, then deep
dive (data model, caching, sharding, queues). Discuss trade-offs explicitly.

## Common mistakes
Jumping to code before clarifying; not stating complexity; ignoring edge cases
(empty input, duplicates, overflow); silence while thinking; over-engineering.

## Questions to ask interviewers
Ask about the team's biggest technical challenge, how success is measured, and what
a typical project looks like. Thoughtful questions signal genuine interest.
